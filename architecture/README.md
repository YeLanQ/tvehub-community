# TvE Hub 架构文档

> 适用分支：`base`（开源社区分支），对应 v1.0.0+2。
> 这套文档描述的是**已经落在代码里的设计**，不是未来规划。每篇末尾列出事实源文件；
> 若文档与代码不一致，以本分支代码为准。

## 文档库定位

`architecture/` 是一个独立的开源架构文档库，随 `base` 分支以 Apache-2.0 发布。
它和另外两个目录不是一回事：

- **`public/docs/`** 是应用内用户手册（编辑器操作、SDK 教程、API 参考），回答
  “怎么用”；本库回答“为什么这样设计、边界在哪里”。
- **`public/repos/`** 是创意工坊的资源库（脚本原型、着色器效果），是可被项目
  引用的资产；本库不放可执行资产。
- 本库不依赖应用运行，单独阅读也能理解整体架构；代码路径只是事实源索引。

这三者分开维护，避免“产品手册被架构讨论淹没”，也避免“架构文档被版本化的用户
教程绑死”。

## 这套文档在回答什么问题

市面上已经有大量“AI + 三维/游戏编辑器”的演示：模型生成一段代码、一张截图，或者
在画布上模拟几次点击，看起来什么都能做。但真正把工具交给 Agent 之后，问题会立刻
变成另外几个：

1. Agent 怎么知道“加一个节点”在这个应用里到底意味着什么？
2. 它怎么在无人盯着的时候，不把项目写坏、不越过用户边界？
3. 它怎么确认自己做对了，并且把结果交付成用户能直接使用的产物，而不是一个演示？
4. 外部 Agent（Claude、Cursor、自动化脚本）和内置助手，是否要维护两套能力？

TvE Hub 的答案不是“给编辑器加一个聊天框”，而是把 **Agent 当成应用的一等公民**：
能力先被设计成原子命令，执行权收归本地后端，协议只是同一能力面的不同投影，最后
由构建管线把操作变成可交付产物。

## 一句话结论

> **模型只负责提出“调哪个命令、传什么参数”；能不能执行、以什么边界执行、执行后
> 如何记账和验证，全部由本地后端决定。**

这句话拆开就是本目录的七篇文章。

## 为什么这不是“给编辑器加一个 AI 插件”

“插件”通常有两种形态，各自有硬伤：

**第一种是屏幕自动化。** 外部 Agent 截屏、识别控件、模拟鼠标键盘。它对 UI 的任何
改动都脆弱，无法知道操作的语义，也无法保证原子性和撤销；遇到弹窗、分辨率变化、
多窗口就失效。它看起来什么都能点，实际上什么都不可靠。

**第二种是直接改文件或直接调内部函数。** Agent 绕过 UI 写 `.scene`、改内存对象，
短期演示很惊艳，但缺少三样东西：写前校验、写后撤销、并发与顺序保证。项目一旦被
写坏，用户只能靠备份恢复。

TvE Hub 选择的是第三条路：**先把“可被操作的能力”做成稳定的方法契约，再让所有
入口——工具栏、快捷键、右键菜单、TCP 客户端、MCP 客户端、内置助手——都走同一套
契约。** 前端命令注册表负责编辑器语义操作，纯后端方法由 Rust 本地执行器应答；
两者共享权限门与数据/引擎校验。

这带来四个直接结果：

- **语义唯一。** “删除节点”在 UI 和 Agent 那里是同一个底层命令（`node.delete`，
  远程方法名 `node.remove`），不是两段各写各的逻辑。
- **边界唯一。** 权限、格式锁、路径检查、撤销历史都收敛到同一条门控与校验路径上，
  不会出现“UI 路径安全、Agent 路径绕过”的漏洞。
- **可观测。** 每次调用都有方法名、参数、结果、耗时和来源，能进日志、能进大脑台账。
- **可替换。** 换一个模型、换一个 MCP 客户端、换一个渲染后端，能力面不变。

## 从一句话到可交付产物

一个真实的建造任务不是“生成一段场景 JSON”，而是一条有依赖的链。下面这条链在
当前实现里是完整可跑的（方法名即 TCP/MCP 方法名）：

```text
用户：做一个带旋转方块的项目，导出单页网页

  project.create       在磁盘上创建项目（模板、场景、配置）
        │
  project.open         打开编辑器窗口并装载项目
        │
  node.add             加立方体 / 灯光 / 相机
  node.set             设置变换、可见性、标签
  node.component.add   挂脚本组件（如 src/Rotator.ts）
  asset.write          写脚本 / 文档 / 普通 JSON 文本
  scene.write          整体回写 .scene（先过引擎格式校验）
  shader.write         整体回写 .shader（先过引擎解析校验）
        │
  scene.save           保存场景（后端会话快照）
  preview.start        导出预览并启动本地服务
  preview.screenshot   截取视口，返回 base64 PNG（可留档到 .tmp/devtools/）
        │
  project.build        走构建管线，产出 build/web/（或单页 index.html）
```

这条链里有三个关键点，是“演示”与“产物”的分水岭：

1. **状态是权威的。** 场景的权威状态在 Rust 后端（`src-tauri/src/scene/`），前端
   `SceneClient` 只是镜像。命令写入后要提交后端、进入撤销历史，失败会回滚镜像。
2. **写前有校验。** `.scene` 必须能按引擎的 `NodeData` 反序列化；`.shader` 必须能
   通过引擎的解析器；引擎管理格式（`.meta/.fsm/.bt/.mat/.terrain/...`）禁止通用
   文本直写。Agent 不是“想写什么就写什么”。
3. **交付有出口。** `project.build` 不是截图或演示，它走真实构建管线，产出可部署的
   Web 产物（单页或多页目录）。构建管线本身也支持微信小游戏渠道，但由构建面板
   发起；远程 `project.build` 当前固定 Web 渠道。

换句话说：**Agent 的最后一个动作不是“告诉你它做了什么”，而是“产出一个你可以
直接打开或部署的东西”。**

## 安全不是一个“允许/禁止”开关

把权限做成一个布尔值，通常会落到两个极端：全开，Agent 很能干但很危险；全关，
Agent 什么都做不了。TvE Hub 用的是分层的门，每一层回答不同的问题：

```text
外部世界
   │
   ├─ G0 网络边界：只绑定 127.0.0.1，不对外监听
   │
   ├─ G1 能力开关：开发者服务是否启用、哪些工具被用户勾选启用
   │
   ├─ G2 行动三区（助手路径）：绿灯只读直接做；黄灯写操作需任务级批准；
   │                          红灯禁止；未登记方法永远按黄灯（且不吃审批豁免）
   │
   ├─ G3 数据边界：工作区相对路径、拒绝 .. 与反斜杠、internal/ 只读、
   │              引擎管理格式锁定、写入体积上限
   │
   ├─ G4 引擎校验：场景按 NodeData 校验、着色器按解析器校验
   │
   └─ G5 审计与观测：统一调用日志、决策计数、执行台账、截图验证
```

需要特别说明的是：**G2 的“任务级批准”只作用于内置助手路径。** 外部 TCP/MCP
客户端走 G0 + G1 + G3 + G4，不弹每动作确认——它们是“用户主动接入的自动化”，不是
“模型自主提议”。这个差异在 [05 权限门](05-permission-gate.md) 里有完整说明，
包括当前版本没有把 token 当作鉴权凭据这一事实。安全文档必须如实描述边界，否则
它只是营销材料。

## 两套协议，一张能力面

```text
                       ┌──────────────────────────────┐
  内置助手（进程内） ──▶│ devtools_internal_call       │
                       │  权限门 → 本地直答 / 编辑器   │
                       └──────────────┬───────────────┘
                                      │
  TCP 客户端 ──JSON Lines──▶ devtools TCP 服务 ──┤
                                      │          ├──▶ 同一方法名
  MCP 客户端 ──JSON-RPC───▶ /mcp 或 mcp.exe ─────┘          │
                                                             ▼
                                                方法执行
                                        （前端命令注册表 / Rust 本地方法）
                                                             │
                                                             ▼
                                                  场景后端 / 文件 / 预览 / 构建
```

- **TCP（换行分隔 JSON）** 是开发者服务的原生接口：持久连接、任意请求 id、服务端
  可推送事件、适合脚本与 CI，延迟最低；**外部 Agent 工具只要能说 JSON Lines，
  就可以直接连上开发者服务驱动编辑器**。
- **MCP（JSON-RPC）** 是同一开发者服务提供的标准接口：标准握手、`tools/list`
  发现、`tools/call` 调用，支持 streamable HTTP 与 stdio 桥，面向 Claude Desktop、
  Cursor 等 MCP 宿主。
- **进程内通道** 是内置助手用的第三条路径：不走 TCP socket，但共享同一套权限门
  与执行器。

TCP 与 MCP 不是两个独立服务：它们同属首页的「开发者服务」，共用同一端口、同一
方法表、同一套工具权限和同一份调用记录。切换接口不会切换能力面。

三者最终都落到同一张方法表；前端方法落同一命令注册表，纯后端方法落 Rust 本地
执行器。**双协议不是双实现**，这是 [03 两套协议](03-dual-protocols.md) 的核心
论点。

### 外部 Agent 接入后，TvE Hub 里看到什么

- **操作直接发生在编辑器里。** 外部 Agent 通过 TCP 发来的 `node.add`、`node.set`、
  `preview.start` 等命令，最终在活跃编辑器窗口执行；节点、场景、预览的变化会
  像用户自己操作一样显示出来，文件写入会落盘并由文件监听刷新。不存在“影子会话”。
- **调用有记录。** 开发者服务面板的「最近调用」会记录来源（`control` / `assistant`）、
  方法、是否成功、耗时和结果摘要；外部 Agent 的每次命令调用都在里面。
- **Agent 的文本由 Agent 自己呈现。** TvE Hub 不解析外部 Agent 的对话文本，也不替
  它聊天；它负责执行命令、把结果可视化，并记录调用。Agent 若需要确认画面，可以
  显式调用 `preview.screenshot`。
- **前提是连上开发者服务。** 服务未启用或端口不通，TCP/MCP 都不可用；这是统一的
  能力总闸。

## “一等公民”的判据

| 维度 | 插件式 Agent | TvE Hub 的内置助手 |
| --- | --- | --- |
| 运行位置 | 外部进程 / 浏览器扩展 | 应用内的原生 Tauri 窗口 `assistant` |
| 感知方式 | 截屏、OCR、模拟输入 | 直接读项目、场景、资产、运行状态 |
| 操作方式 | 点击坐标 / 调外部 API | 调原子命令，与 UI 同一执行器 |
| 权限 | 难以约束（能点就能做） | 五道门 + 任务级批准 + 调用日志 |
| 知识 | 每次从零提示 | 技能/文档构建期内嵌，工坊资源运行时同步 |
| 验证 | 看截图猜 | 预览 + 截图 + 构建产物 |
| 失败恢复 | 重新点一遍 | 撤销历史 / 回滚 / 错误回喂自纠 |

“一等公民”不是指模型更强，而是指**它的能力、权限、知识和验证方式，和应用本身
长在同一套体系里**。

## 阅读约定

- **方法（method）**：TCP/MCP 对外的稳定调用名，如 `node.add`。
- **命令（command）**：前端命令注册表里的实现单元，id 通常与方法同名或有一一映射。
- **工具（tool）**：权限面板里可勾选的能力组，如 `nodeAdd` 覆盖 `node.add`。
- **大脑（brain）**：Rust 侧的确定性策略层，负责检索、拆解、门控、观测，不调 LLM。
- **绿灯/黄灯/红灯**：行动边界三区，定义在 `src-tauri/src/brain/policy/zones.rs`。
- **审批会话**：用户批准某个任务后，10 分钟内该任务的黄灯调用可直接放行。
